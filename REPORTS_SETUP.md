# Автоматична звітність NOROV CRM

Ця збірка додає налаштування звітності та серверну функцію. Встановлення frontend саме по собі не запускає звіти. Спочатку виконайте одноразове підключення нижче. Make для звітності не використовується.

## 1. Оновіть сайт

Збережіть свій `.env.local` з VITE_SUPABASE_URL та VITE_SUPABASE_PUBLISHABLE_KEY. Вони не включені в архів. Не додавайте серверні секрети до VITE-змінних.

```bash
npm ci
npm run build
```

Розгорніть `dist` на поточному хостингу або завантажте оновлені вихідні файли в GitHub для автоматичної збірки. Клієнти та оплати залишаються в наявній базі.

## 2. Додайте таблиці звітності

У Supabase → SQL Editor виконайте **лише новий** файл `supabase/migrations/20261008132216_client_reports.sql`. Старі міграції вдруге виконувати не треба. Якщо користуєтеся CLI з узгодженою історією міграцій, можна застосувати його через ваш звичайний процес міграцій.

Таблиці налаштувань доступні тільки серверній функції. Токени ботів, Meta та Google шифруються AES-GCM. CRM не повертає збережені токени в браузер. Технічні записи доставки зберігають лише ключ періоду та стан, без чисел звіту; вони потрібні для захисту від дублів.

## 3. Серверні секрети та функція

Supabase → Authentication → Users: скопіюйте UUID свого користувача CRM.

Supabase → Edge Functions → Secrets додайте:

- `REPORTS_OWNER_ID` — цей UUID. Спільна інтеграція обслуговує клієнтів лише цього власника.
- `REPORTS_ENCRYPTION_KEY` — 32 випадкових байти у base64. Для генерації на Mac: `openssl rand -base64 32`. Збережіть ключ; його заміна без перенесення зашифрованих даних зробить старі токени недоступними.
- `REPORTS_CRON_SECRET` — окремий випадковий секрет. Генерація: `openssl rand -hex 32`.
- `META_API_VERSION` — `v26.0`.

Стандартні SUPABASE_URL та SUPABASE_SERVICE_ROLE_KEY використовуються тільки всередині функції. Не вставляйте service_role у сайт.

У Terminal у папці збірки:

```bash
npx supabase login
npx supabase functions deploy client-reports --project-ref YOUR_PROJECT_REF
```

У config.toml для цієї функції verify_jwt=false: функція сама перевіряє JWT через auth.getUser і власника клієнта. Заплановані виклики перевіряють окремий REPORTS_CRON_SECRET. Не прибирайте ці перевірки.

## 4. Meta та Google — один раз для всіх клієнтів

У CRM → Інтеграції → «Meta → Google → Telegram»:

1. Вставте Meta Access Token з ads_read і доступом до рекламних кабінетів. Користувацький токен має строк дії; перед його завершенням вставте новий. Автоматичне продовження токена в цю версію не входить.
2. Google Cloud: увімкніть Google Sheets API, створіть Service Account і його JSON-ключ.
3. Вставте повний JSON у поле Google та збережіть.
4. CRM покаже email сервісного акаунту. У кожній клієнтській Google Таблиці надайте цьому email право **Редактор**. Публічний доступ до таблиці не потрібен.

За бажанням адміністратор може зберігати META_ACCESS_TOKEN та GOOGLE_SERVICE_ACCOUNT_JSON у серверних Secrets замість полів CRM. Збережене через CRM підключення має пріоритет.

## 5. Перший тест Capital Job

У картці Capital Job → «Автоматичні звіти»:

- ID кабінету: `378174569508694`.
- Таблиця: `https://docs.google.com/spreadsheets/d/1GsE79cFsGKLT5MSiT6lLwL6-wHWyAQRrZHFpDw63SSM/edit`.
- Введіть chat ID тестової групи та токен її бота. Бот має бути учасником із правом надсилання.
- Дату початку встановіть на день, з якого потрібні автоматичні звіти.
- Спочатку залиште автоматичні звіти вимкненими й натисніть «Зберегти звітність».

Послідовність кнопок:

1. «Перевірити підключення» — читання доступів, без надсилання повідомлення.
2. Дата тесту `2026-10-07` → «Переглянути звіт» — без запису і надсилання.
3. «Записати в Google» — автоматично створить вкладку **Meta — щодня**.
4. «Google + тест у Telegram» — оновить таблицю та надішле повідомлення з позначкою ТЕСТ.

Раніше отриманий API-знімок цього дня: 26 лідів, 67,54 USD, 7122 показів, 84 кліки. Повторний запит бере поточні дані Meta; вони можуть змінитися через дооблік. Старі місячні вкладки й ручні числа не змінюються. Новий звіт повністю автоматичний.

## 6. Розклад

У Supabase увімкніть розширення pg_cron та pg_net. У Vault створіть два секрети:

- `norov_reports_url`: `https://YOUR_PROJECT_REF.supabase.co/functions/v1/client-reports`.
- `norov_reports_cron`: те саме значення, що у REPORTS_CRON_SECRET функції.

Потім виконайте `supabase/reports_schedule.sql` у SQL Editor. Перевірка кожні 5 хвилин: щоденний звіт після 08:10 за вчора; щотижневий після 09:00 у понеділок за попередній понеділок–неділю. Час визначається у Europe/Warsaw незалежно від часу cron (UTC) або комп'ютера. Допускається затримка виконання сервісом.

У картці активного клієнта увімкніть автоматичні звіти та потрібні періоди. CRM не потрібно тримати відкритою.

Пауза/архів зупиняють запис і надсилання. Після повернення в активні початок автоматизації оновлюється на дату повернення. Тиждень надсилається лише якщо весь попередній тиждень входить у активний період. Автоматичного надсилання пропущених днів немає; окремий завершений день можна вивантажити кнопкою тесту.

## Як рахуються результати

- Запит охоплює всі кампанії та групи кабінету без фільтра «активні зараз».
- Стандартні ліди: action_type `lead`. Дублюючі lead_grouped, search/registration та інші загальні метрики до них не додаються.
- Для груп зі спеціальною конверсією функція читає promoted_object.custom_conversion_id із Meta, перевіряє, що конверсія позначена LEAD або має Lead у назві, і бере її значення замість загального lead у цій групі. Це підтримує різні групи з різними конверсіями. Невизначений тип блокує звіт із поясненням, щоб не показувати вигадане число.
- AdsQuiz напряму не підключається. Перевірте перший звіт такого клієнта проти Ads Manager за той самий період. Якщо Meta використовує custom event без custom_conversion_id, потрібне уточнення mapping за реальною відповіддю API; ця збірка не вгадує назву події.
- Переписки: `onsite_conversion.messaging_conversation_started_7d`, окремо від лідів. Це не вивантаження текстів і не весь органічний Direct; без додаткової розбивки не називаємо його суто Instagram.
- Використовуються налаштування атрибуції груп. Дні рекламної статистики відповідають часовому поясу рекламного кабінету; розклад — Варшаві.
- Числа — рекламні результати Meta, а не унікальні контакти після CRM-дедуплікації. Валюта береться з поля currency кабінету. Автоконвертації немає.
- Тижневі коефіцієнти рахуються із сум, не як середнє денних коефіцієнтів.

## Помилки та повтори

Таблиця оновлює рядок за повною датою YYYY-MM-DD, без створення дублів. Один тестовий Telegram-звіт для клієнта та дня надсилається один раз; запланований звіт має окремий ключ.

При невизначеному результаті відправлення Telegram (наприклад, мережевий таймаут) автоповтор блокується: повідомлення могло вже дійти. Перевірте чат. Для підтвердженого ненадсилання адміністратор може видалити конкретний технічний запис у client_report_delivery, після чого повторити. Усі записи масово не очищайте. Помилка одного клієнта не зупиняє інші.

У цій версії немає історії звітів у CRM, місячних звітів та автоматичного поновлення Meta-токена. Наявні Google-рядки оновлюються при повторному ручному/тижневому запиті; щоденне планове повідомлення повторно не надсилається.

## JWT

Додано автоматичне поновлення токена та один повтор відхиленого JWT-запиту до бази/функцій. Успішні операції, загальні мережеві помилки та відмови у правах не повторюються. Паралельні поновлення сесії об'єднуються. При відкритті та поверненні до вкладки сесія перевіряється сервером. Недійсний refresh token потребує повторного входу.

Неправильний системний час на комп'ютері може заважати бібліотеці авторизації. Код не змінює годинник і не обходить перевірку JWT. На macOS дата/час бажано автоматичні; сам вибір часового поясу не змінює строк дії JWT. Точна причина попереднього збою без тексту помилки/журналів не підтверджена.

## Перевірки збірки

Frontend: TypeScript + production build. Автотести підрахунків: дублюючі метрики, порожні дні, USD/PLN, межа тижня/року, Warsaw DST. Автотест JWT-повтору перевіряє збереження тіла PATCH та відсутність повтору при 403. Живі Meta/Google/Telegram і базова міграція потребують перевірки після підключення вашого Supabase.
