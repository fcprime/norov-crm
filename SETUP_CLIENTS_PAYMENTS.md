# NOROV CRM — модуль клієнтів та оплат

## Що додано
- Огляд із простроченими та найближчими оплатами.
- Клієнти: Активні / Пауза / Архів.
- Картка клієнта: тариф, цикл оплати, наступна дата, джерело, контакт, нотатки.
- Кнопка «Оплачено»: записує платіж та автоматично переносить наступну дату.
- Історія оплат та LTV клієнта.
- Повернення клієнта з паузи/архіву без втрати історії.
- Існуюча вкладка «Ліди» збережена.

## Перший запуск
```bash
npm install
npm run dev
```

## Supabase
CRM може відкритися навіть без нових таблиць — тоді модуль клієнтів/оплат тимчасово працює через localStorage.
Щоб дані синхронізувалися між пристроями, виконайте SQL:

`supabase/migrations/20260908_clients_payments.sql`

У Supabase Dashboard: SQL Editor → New query → вставити весь SQL → Run.

Після цього клієнти й оплати зберігаються у Supabase та захищені RLS за owner_id.

## Логіка продовження
Клієнта не потрібно створювати щомісяця. Після платежу натисніть «Оплачено».
CRM:
1. записує платіж в історію;
2. додає суму до LTV;
3. зберігає планову та фактичну дату;
4. переносить наступну оплату на наступний цикл.

## Статуси
- Active — контролюється наступна оплата.
- Pause — не рахується як прострочений.
- Archive — співпраця завершена, але LTV та історія зберігаються.

## Оновлення 09.09 — переведення ліда в клієнта

У картці існуючого ліда з'явилась кнопка **«Перевести в клієнти»**.
CRM автоматично переносить ім'я, телефон/WhatsApp, послугу, джерело, суму ліда, кампанію, відповіді форми та робочу примітку. Перед збереженням відкривається картка нового клієнта, де потрібно перевірити/дозаповнити суму, дату старту, наступну оплату і цикл.

Щоб зв'язок «лід → клієнт» зберігався у Supabase, після основної міграції виконайте також:

`supabase/migrations/20260909_client_lead_link.sql`

Якщо таблиці `clients` і `payments` ще не створювалися, достатньо виконати актуальну `20260908_clients_payments.sql`, а потім безпечно виконати `20260909_client_lead_link.sql` — повторний запуск не зашкодить.
