# Оновлення звітності 0.12.0

## Встановлення

1. Збережіть свої локальні .env.local, .env.functions та JSON Google. Їх немає в цій збірці. Замініть файли проекту в поточній папці, збережіть власну .git і налаштування підключення.
2. У Supabase SQL Editor виконайте тільки новий файл `supabase/migrations/20261008205023_report_sheet_target.sql`. Старі міграції повторно не запускайте. Він додає поле вибору аркуша й не змінює поточні дані/секрети/розклад.
3. У терміналі папки проекту:

```bash
npx supabase functions deploy client-reports --project-ref ltdxqqukbsbxwnjxbuti
```

4. Оновіть сайт звичайним завантаженням змін у свій GitHub/деплоєм. Для локальної перевірки `npm run build`.
5. Vault, REPORTS_CRON_SECRET, REPORTS_ENCRYPTION_KEY, Google JSON і розклад залишаються тими самими. Не створюйте розклад заново.

## CapitalJob — продовжити поточний аркуш

У картці клієнта:

- Початок звітності: **08.10.2026** (дата початку автоматичного заповнення, не початок місяця співпраці).
- Куди записувати → **Мій наявний аркуш**.
- Натисніть **Завантажити аркуші таблиці**, оберіть **Вересень**.
- Період аркуша: **24.09.2026–23.10.2026**, останній день включно.
- Перший рядок з датою: **2**; останній: **31**. Це відповідає надісланому скриншоту; рядок 32 «Загалом» не включайте.
- Колонки: A дата, B кампанії, C ліди, D CPL, E CPM, F покази, G CPC, H кліки, I CTR, J витрати. Переписки й валюту залиште порожніми, якщо в шаблоні таких колонок немає. У Telegram переписки та валюта залишаються.
- Натисніть **Зберегти звітність**. Перевірте збереження, повторно відкривши картку.
- Автоматичні звіти + Щодня о 08:10 залиште увімкненими, клієнт активний.

Щоб перевірити запис за 08.10, дочекайтеся завершення дня й 09.10 оберіть дату тесту 08.10. Спершу «Переглянути звіт»: він покаже аркуш і кількість днів, які буде записано, але нічого не змінює. Потім «Записати в Google» — без додаткового Telegram-повідомлення. Якщо автоматизація вже заповнила цей рядок, він буде пропущений.

## Правила запису

- Аркуш зберігається за ID (gid), тому його перейменування не порушує прив’язку. Вибір іншої Google-таблиці скидає прив’язку; оберіть аркуш заново.
- Дати в обраній колонці вже мають існувати. Підтримуються справжні дати Google, YYYY-MM-DD, DD.MM, DD.MM.YYYY, DD/MM. Рік для коротких дат визначається з періоду; неоднозначність зупиняє запис. Дублі або відсутня потрібна дата також зупиняють запис до змін.
- Запис лише в налаштовані клітинки порожнього рядка, за відповідною датою і не раніше початку звітності. Будь-яке вже заповнене поле серед обраних колонок даних (у тому числі 0 чи формула) захищає весь рядок. Частково заповнені рядки пропускаються цілком.
- Ручні та вже автоматично заповнені рядки не перераховуються. Якщо потрібне повторне завантаження змінених Meta-даних, свідомо очистіть тільки налаштовані клітинки даних потрібного дня, збережіть дату й натисніть «Записати в Google».
- Кольори, межі, висоти, ширини, шрифти, дати, заголовки й підсумкові формули зберігаються. Лише числовий формат записуваних грошових клітинок та CTR задається заново, щоб валюта відповідала Meta, а CTR був відсотком. Формули підсумків перераховує Google, якщо вони вже є; їх правильність система не змінює і не перевіряє.
- На наступний період підготуйте аркуш із датами, оберіть його та задайте новий період/рядки. Початок звітності залиште 08.10, якщо співпраця не переривалася. Автоматичного створення чи перемикання місячних аркушів у цій версії немає.
- Вихід дати за період зупиняє запис і відповідне надсилання, показує помилку в CRM. Для тижневого звіту всі дні, що записуються, мають входити в обраний аркуш; тиждень через межу двох аркушів ця версія не розподіляє.
- Telegram містить фактичні дані Meta, навіть якщо відповідний рядок таблиці пропущений як уже заповнений. Тест і планове надсилання мають окремі ключі захисту від дублів.

## Перевірки збірки

Пройдено: TypeScript фронтенду, production build, типи Edge Function (з локальною підстановкою npm-імпорту), тести дат/валют/атрибуції, JWT retry, вибору рядків/періодів/колонок та запитів Google з імітацією API. Реальні API Meta/Google, міграцію й деплой цієї версії потрібно перевірити після встановлення; доступ до вашого сервера з цієї перевірки не використовувався.
